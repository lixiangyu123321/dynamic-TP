## 概述

DynamicTp 框架通过**适配器模式**统一管理第三方中间件内部的线程池，实现了对多种中间件线程池的统一管理、动态调参、监控告警等功能。

### 核心价值

1. **统一管理**: 将不同中间件的线程池统一纳入框架管理
2. **动态调参**: 运行时动态调整线程池参数，无需重启应用
3. **监控告警**: 实时监控线程池状态，异常及时告警
4. **功能增强**: 为第三方线程池添加框架的监控、任务包装等功能
5. **无侵入性**: 通过代理和反射技术，无需修改中间件源码

### 解决的问题

- **线程池分散**: 不同中间件使用各自的线程池，难以统一管理
- **参数固化**: 线程池参数在启动时确定，无法根据负载动态调整
- **监控缺失**: 缺乏统一的监控和告警机制
- **配置复杂**: 每个中间件需要单独配置，配置分散

### 核心设计模式

1. **适配器模式**: `DtpAdapter` 接口适配不同中间件
2. **代理模式**: `ThreadPoolExecutorProxy` 代理原始线程池
3. **包装器模式**: `ExecutorWrapper` 包装线程池和元数据
4. **观察者模式**: 事件总线监听配置变更、监控采集等事件

## 核心组件

### 1. DtpAdapter（适配器接口）

`DtpAdapter` 是适配器的核心接口，定义了适配器的基本功能。

#### 接口定义

```java
public interface DtpAdapter extends MetricsAware {
    // 获取单个线程池包装器
    default ExecutorWrapper getExecutorWrapper() {
        return null;
    }
    
    // 获取所有线程池包装器
    default Map<String, ExecutorWrapper> getExecutorWrappers() {
        return Collections.emptyMap();
    }
    
    // 刷新线程池配置
    void refresh(DtpProperties dtpProperties);
    
    // 参数校验
    default boolean containsInvalidParams(TpExecutorProps props, Logger log) {
        // 校验核心线程数、最大线程数等参数
    }
}
```

#### 核心职责

- **线程池发现**: 自动发现中间件内部的线程池实例
- **配置刷新**: 响应配置中心的配置变更
- **指标提供**: 实现 `MetricsAware` 接口，提供线程池统计信息

### 2. AbstractDtpAdapter（适配器抽象基类）

`AbstractDtpAdapter` 实现了适配器的通用逻辑，子类只需实现特定的线程池发现逻辑。

#### 核心方法

**初始化流程**

```java
@Subscribe
public synchronized void onContextRefreshedEvent(CustomContextRefreshedEvent event) {
    DtpProperties dtpProperties = ContextManagerHelper.getBean(DtpProperties.class);
    initialize();              // 子类实现：发现线程池
    afterInitialize();          // 注册到感知器
    refresh(dtpProperties);     // 应用配置
}
```

**线程池增强**

```java
protected void enhanceOriginExecutor(String tpName, ThreadPoolExecutor executor, 
                                     String fieldName, Object targetObj) {
    // 1. 创建代理对象
    ThreadPoolExecutorProxy proxy = new ThreadPoolExecutorProxy(executor);
    
    // 2. 通过反射替换原始线程池
    boolean r = ReflectionUtil.setFieldValue(fieldName, targetObj, proxy);
    
    // 3. 注册到框架并关闭原始线程池
    if (r) {
        putAndFinalize(tpName, executor, proxy);
    }
}
```

**配置刷新**

```java
protected void doRefresh(ExecutorWrapper executorWrapper,
                         List<NotifyPlatform> platforms,
                         TpExecutorProps props) {
    val executor = executorWrapper.getExecutor();
    
    // 1. 刷新线程池大小
    doRefreshPoolSize(executor, props);
    
    // 2. 刷新空闲时间
    executor.setKeepAliveTime(props.getKeepAliveTime(), props.getUnit());
    
    // 3. 更新别名
    executorWrapper.setThreadPoolAliasName(props.getThreadPoolAliasName());
    
    // 4. 更新任务包装器
    executorWrapper.setTaskWrappers(taskWrappers);
    
    // 5. 更新通知配置
    updateNotifyInfo(executorWrapper, props, platforms);
    
    // 6. 刷新感知器配置
    AwareManager.refresh(executorWrapper, props);
}
```

### 3. ThreadPoolExecutorProxy（线程池代理）

`ThreadPoolExecutorProxy` 是线程池的代理类，继承自 `ThreadPoolExecutor`，用于增强原始线程池的功能。

#### 核心功能

```java
public class ThreadPoolExecutorProxy extends ThreadPoolExecutor 
        implements TaskEnhanceAware, RejectHandlerAware {
    
    private List<TaskWrapper> taskWrappers;  // 任务包装器
    private String rejectHandlerType;        // 拒绝策略类型
    
    public ThreadPoolExecutorProxy(ThreadPoolExecutor executor) {
        // 复制原始线程池的所有参数
        super(executor.getCorePoolSize(), executor.getMaximumPoolSize(),
              executor.getKeepAliveTime(TimeUnit.MILLISECONDS), TimeUnit.MILLISECONDS,
              executor.getQueue(), executor.getThreadFactory(),
              executor.getRejectedExecutionHandler());
        
        // 使用代理拒绝策略（支持告警等功能）
        setRejectedExecutionHandler(
            RejectHandlerGetter.getProxy(getRejectedExecutionHandler())
        );
    }
    
    @Override
    public void execute(Runnable command) {
        // 1. 任务包装（上下文传递等）
        command = getEnhancedTask(command);
        
        // 2. 感知器处理（监控、超时等）
        AwareManager.execute(this, command);
        
        // 3. 委托给父类执行
        super.execute(command);
    }
}
```

#### 增强功能

1. **任务包装**: 支持任务包装器（上下文传递、日志增强等）
2. **感知器支持**: 集成 `AwareManager`，支持监控、超时、拒绝等感知器
3. **拒绝策略增强**: 使用代理拒绝策略，支持告警等功能
4. **生命周期钩子**: 支持 `beforeExecute`、`afterExecute` 等钩子

### 4. ExecutorWrapper（执行器包装器）

`ExecutorWrapper` 包装线程池实例和元数据，提供统一的管理接口。

#### 核心属性

```java
public class ExecutorWrapper {
    private String threadPoolName;           // 线程池名称
    private String threadPoolAliasName;      // 线程池别名
    private ExecutorAdapter<?> executor;    // 执行器适配器
    private ThreadPoolStatProvider statProvider;  // 统计提供者
    // ... 其他元数据
}
```

#### 核心功能

- **统一接口**: 通过 `ExecutorAdapter` 统一不同执行器的接口
- **元数据管理**: 集中管理线程池的元数据
- **功能增强**: 提供任务包装、拒绝策略增强等功能
- **统计支持**: 持有 `ThreadPoolStatProvider`，提供性能统计

### 5. DtpAdapterListener（适配器监听器）

`DtpAdapterListener` 监听框架事件，统一处理所有适配器的事件。

#### 事件处理

```java
@Subscribe
public void handleDtpEvent(EventObject event) {
    if (event instanceof RefreshEvent) {
        // 配置刷新事件
        doRefresh(refreshEvent.getDtpProperties());
    } else if (event instanceof CollectEvent) {
        // 监控采集事件
        doCollect(collectEvent.getDtpProperties());
    } else if (event instanceof AlarmCheckEvent) {
        // 告警检查事件
        doAlarmCheck(alarmCheckEvent.getDtpProperties());
    }
}
```

#### 统一处理

```java
protected void doRefresh(DtpProperties dtpProperties) {
    // 获取所有适配器
    val handlerMap = ContextManagerHelper.getBeansOfType(DtpAdapter.class);
    
    // 统一刷新所有适配器的线程池
    handlerMap.forEach((k, v) -> v.refresh(dtpProperties));
}
```

## 工作流程

### 1. 初始化流程

```
Spring 容器启动
    ↓
发布 CustomContextRefreshedEvent 事件
    ↓
AbstractDtpAdapter.onContextRefreshedEvent()
    ↓
initialize() - 子类实现线程池发现
    ↓
afterInitialize() - 注册到 AwareManager
    ↓
refresh() - 应用配置
    ↓
完成初始化
```

### 2. 线程池发现流程

以 Dubbo 适配器为例：

```java
@Override
protected void initialize() {
    // 1. 获取 ExecutorRepository（Dubbo 的线程池仓库）
    ExecutorRepository executorRepository = 
        ApplicationModel.defaultModel()
            .getExtensionLoader(ExecutorRepository.class)
            .getDefaultExtension();
    
    // 2. 通过反射获取线程池 Map
    val data = (ConcurrentMap<String, ConcurrentMap<Object, ExecutorService>>) 
        ReflectionUtil.getFieldValue(DefaultExecutorRepository.class, "data", executorRepository);
    
    // 3. 遍历所有线程池
    Map<Object, ExecutorService> executorMap = data.get(EXECUTOR_SERVICE_COMPONENT_KEY);
    executorMap.forEach((k, v) -> {
        // 4. 创建代理对象
        ThreadPoolExecutor proxy = getProxy(v);
        
        // 5. 替换原始线程池
        executorMap.replace(k, proxy);
        
        // 6. 注册到框架
        putAndFinalize(genTpName(k.toString()), (ExecutorService) v, proxy);
    });
}
```

### 3. 配置刷新流程

```
配置中心配置变更
    ↓
发布 RefreshEvent 事件
    ↓
DtpAdapterListener.handleDtpEvent()
    ↓
doRefresh() - 获取所有适配器
    ↓
AbstractDtpAdapter.refresh()
    ↓
doRefresh() - 刷新单个线程池
    ├─ 刷新线程池大小
    ├─ 刷新空闲时间
    ├─ 更新任务包装器
    ├─ 更新通知配置
    └─ 刷新感知器配置
    ↓

```

### 4. 监控采集流程

```
定时任务触发
    ↓
发布 CollectEvent 事件
    ↓
DtpAdapterListener.handleDtpEvent()
    ↓
doCollect() - 获取所有适配器
    ↓
DtpAdapter.getMultiPoolStats() - 获取统计信息
    ↓
CollectorHandler.collect() - 采集指标
    ↓
```

### 5. 告警检查流程

```

    ↓

    ↓

    ↓

    ↓

    ↓

    ↓
```

### 1. 线程池发现技术

#### 方式1：反射获取

通过反射获取中间件内部的线程池实例：

```java
// 示例：RocketMQ 适配器
val consumeMessageService = pushConsumer.getConsumeMessageService();
ThreadPoolExecutor executor = (ThreadPoolExecutor) 
    ReflectionUtil.getFieldValue(consumeMessageService.getClass(),
                                 CONSUME_EXECUTOR_FIELD, 
                                 consumeMessageService);
```

#### 方式2：JVMTI 技术

对于无法通过反射获取的场景，使用 JVMTI 技术：

```java
// 示例：Thrift 适配器
val handlers = JVMTI.getInstances(WrappedChannelHandler.class);
handlers.forEach(handler -> {
    val originExecutor = ReflectionUtil.getFieldValue(EXECUTOR_FIELD, handler);
    // 处理线程池...
});
```

#### 方式3：Spring Bean 获取

对于注册为 Spring Bean 的线程池：

```java
// 示例：从 Spring 容器获取
val beans = ContextManagerHelper.getBeansOfType(DefaultMQPushConsumer.class);
```

### 2. 线程池增强技术

#### 代理替换

通过反射替换原始线程池为代理对象：

```java
protected void enhanceOriginExecutor(String tpName, 
                                     ThreadPoolExecutor executor, 
                                     String fieldName, 
                                     Object targetObj) {
    // 1. 创建代理对象
    ThreadPoolExecutorProxy proxy = new ThreadPoolExecutorProxy(executor);
    
    // 2. 通过反射替换
    boolean r = ReflectionUtil.setFieldValue(fieldName, targetObj, proxy);
    
    // 3. 注册并关闭原始线程池
    if (r) {
        putAndFinalize(tpName, executor, proxy);
    }
}
```

#### 原始线程池关闭

替换后，原始线程池会被优雅关闭：

```java
protected void shutdownOriginalExecutor(ExecutorService executor) {
    shutdownGracefulAsync(executor, getTpPrefix(), 5);
}
```

### 3. 动态调参实现

#### 线程池大小调整

```java
private void doRefreshPoolSize(ExecutorAdapter<?> executor, TpExecutorProps props) {
    // 如果新最大线程数 >= 当前最大线程数，先调大最大线程数，再调核心线程数
    if (props.getMaximumPoolSize() >= executor.getMaximumPoolSize()) {
        if (!Objects.equals(props.getMaximumPoolSize(), executor.getMaximumPoolSize())) {
            executor.setMaximumPoolSize(props.getMaximumPoolSize());
        }
        if (!Objects.equals(props.getCorePoolSize(), executor.getCorePoolSize())) {
            executor.setCorePoolSize(props.getCorePoolSize());
        }
        return;
    }
    
    // 如果新最大线程数 < 当前最大线程数，先调小核心线程数，再调最大线程数
    if (!Objects.equals(props.getCorePoolSize(), executor.getCorePoolSize())) {
        executor.setCorePoolSize(props.getCorePoolSize());
    }
    if (!Objects.equals(props.getMaximumPoolSize(), executor.getMaximumPoolSize())) {
        executor.setMaximumPoolSize(props.getMaximumPoolSize());
    }
}
```

**调整顺序的重要性**：

- **调大**: 先调最大线程数，再调核心线程数（避免核心线程数超过最大线程数）
- **调小**: 先调核心线程数，再调最大线程数（避免线程数突然减少导致任务丢失）

### 4. 变更通知机制

配置刷新后，如果参数有变更，会触发变更通知：

```java
// 获取变更前的参数
TpMainFields oldFields = getTpMainFields(executorWrapper, props);

// 执行刷新
doRefresh(executorWrapper, platforms, props);

// 获取变更后的参数
TpMainFields newFields = getTpMainFields(executorWrapper, props);

// 比较差异
List<FieldInfo> diffFields = EQUATOR.getDiffFields(oldFields, newFields);

// 发送通知
if (!oldFields.equals(newFields)) {
    NoticeManager.tryNoticeAsync(executorWrapper, oldFields, diffKeys);
}
```

## 支持的中间件

### Web 服务器

#### Tomcat

- **适配器**: `TomcatDtpAdapter`
- **线程池类型**: `org.apache.catalina.Executor`
- **发现方式**: 从 `Connector` 获取 `Executor`
- **增强方式**: 使用 `TomcatExecutorProxy` 代理

#### Jetty

- **适配器**: `JettyDtpAdapter`
- **线程池类型**: `org.eclipse.jetty.util.thread.ThreadPool.SizedThreadPool`
- **发现方式**: 从 `Server` 获取 `ThreadPool`
- **增强方式**: 使用 `QueuedThreadPoolProxy` 代理

#### Undertow

- **适配器**: `UndertowDtpAdapter`
- **线程池类型**: `io.undertow.xnio.XnioWorker`
- **发现方式**: 从 `UndertowEmbeddedServletContainerFactory` 获取
- **增强方式**: 使用 `EnhancedQueueExecutorProxy` 代理

### RPC 框架

#### Dubbo

- **适配器**: `ApacheDubboDtpAdapter` / `AlibabaDubboDtpAdapter`
- **线程池类型**: `ThreadPoolExecutor` / `EagerThreadPoolExecutor`
- **发现方式**: 从 `ExecutorRepository` 获取
- **版本兼容**: 支持 2.7.5+ 和 3.x 版本
- **增强方式**: 使用 `ThreadPoolExecutorProxy` 或 `EagerThreadPoolExecutorProxy`

#### gRPC

- **适配器**: `GrpcDtpAdapter`
- **线程池类型**: `ThreadPoolExecutor`
- **发现方式**: 从 `ServerBuilder` 获取

#### Motan

- **适配器**: `MotanDtpAdapter`
- **线程池类型**: `StandardThreadExecutor`
- **发现方式**: 从 `StandardThreadExecutor` 获取
- **增强方式**: 使用 `StandardThreadExecutorProxy` 代理

### 消息队列

#### RocketMQ

- **适配器**: `RocketMqDtpAdapter`
- **线程池类型**: `ThreadPoolExecutor`
- **发现方式**: 
  - 消费者: 从 `ConsumeMessageService` 获取 `consumeExecutor`
  - 生产者: 从 `DefaultMQProducerImpl` 获取 `asyncSenderExecutor`
- **增强方式**: 使用 `ThreadPoolExecutorProxy` 代理

#### RabbitMQ

- **适配器**: `RabbitMqDtpAdapter`
- **线程池类型**: `ThreadPoolExecutor`
- **发现方式**: 从 `ConnectionFactory` 获取

### 其他

#### Hystrix

- **适配器**: `HystrixDtpAdapter`
- **线程池类型**: `ThreadPoolExecutor`
- **发现方式**: 通过 `HystrixConcurrencyStrategy` 拦截
- **增强方式**: 使用 `DtpHystrixConcurrencyStrategy` 替换默认策略

#### OkHttp3

- **适配器**: `OkHttp3DtpAdapter`
- **线程池类型**: `ThreadPoolExecutor`（连接池）
- **发现方式**: 从 `OkHttpClient` 获取 `Dispatcher`

#### Liteflow

- **适配器**: `LiteflowDtpAdapter`
- **线程池类型**: `ThreadPoolExecutor`
- **发现方式**: 从 `FlowExecutor` 获取

```yaml
spring:
  dynamic:

      enabled: true
      dubboTp:                    # Dubbo 线程池配置
        corePoolSize: 200
        maximumPoolSize: 400
        keepAliveTime: 60
        threadPoolAliasName: Dubbo业务线程池

          - type: CAPACITY
```

3. **代理替换**: 使用 `ThreadPoolExecutorProxy` 替换原始线程池
4. **配置应用**: 根据配置刷新线程池参数
5. **监控告警**: 自动采集指标并触发告警

### 如何添加新的适配器

#### 步骤1：创建适配器类


## 总结

DynamicTp 框架通过适配器模式实现了对第三方中间件线程池的统一管理：

1. **统一接口**: `DtpAdapter` 接口统一了不同中间件的适配方式
2. **代理增强**: `ThreadPoolExecutorProxy` 为原始线程池添加了框架功能
3. **自动发现**: 适配器自动发现中间件的线程池实例
4. **动态调参**: 支持运行时动态调整线程池参数
5. **监控告警**: 统一的监控和告警机制
6. **易于扩展**: 通过实现 `DtpAdapter` 接口可以轻松扩展支持新的中间件

这种设计使得框架能够无侵入地管理各种中间件的线程池，实现了真正的统一管理和动态调参能力。
